# Results: blank pages, Windows 11, Intel Core i5-9400F (2026-11-24)

This records one local run of every benchmark currently implemented in the
repository (`EmptyPageBenchmarks`, 1 and 10 blank A4 pages). It is a single
run on a developer desktop, not controlled hardware, so treat it as
informational. Read [methodology](../methodology.md) before interpreting it.

## What was run

- Commit: `5c82d3e7095df7c20e167058e59a48bb29317f46` (clean working tree)
- Packages: UnlimitedPDF 1.1.0, PDFsharp 6.2.4, PdfPig 0.1.16,
  BenchmarkDotNet 0.15.8 (versions from `Directory.Packages.props`, locked
  restore)
- Job: BenchmarkDotNet default job (no `--job` override), MemoryDiagnoser on
- Pre-run checks: locked restore, Release build with 0 warnings, 4 of 4 tests
  passed. The `[GlobalSetup]` validation of page count and A4 dimensions passed
  for all three libraries at both page counts; all 6 cases executed.
- Benchmark run time: 1 min 59 s (2 min 13 s total)

Commands:

```sh
dotnet restore UnlimitedPDF.Benchmarks.slnx --locked-mode
dotnet build UnlimitedPDF.Benchmarks.slnx -c Release --no-restore
dotnet test UnlimitedPDF.Benchmarks.slnx -c Release --no-build --no-restore
dotnet run --project src/UnlimitedPDF.Benchmarks.Runner -c Release --no-build -- --filter '*EmptyPageBenchmarks*'
```

## Observations

- In this run UnlimitedPDF took the least time for both page counts. The
  99.9% confidence intervals do not overlap for any pair.
- PdfPig allocated the least managed memory for both page counts (about 20%
  to 26% less than UnlimitedPDF). PDFsharp allocated the most.
- The ranking between PDFsharp and PdfPig flips with page count: PdfPig is
  faster for 1 page and slower for 10. Per-page cost differs from fixed
  per-document cost, so these two points cannot be extrapolated to larger
  documents.
- None of this generalizes beyond blank pages. Text, fonts, images, layout and
  every other workload in the [feature comparison](../feature-comparison.md)
  are not implemented and were not measured.

## Warnings and statistical notes

- UnlimitedPDF, 10 pages: BenchmarkDotNet reported a possibly multimodal
  distribution (mValue = 3.13). Its mean should be read with more caution than
  the others; a repeat run on a quieter machine would tell whether this is
  noise.
- Outliers removed by BenchmarkDotNet (all 1-page cases): UnlimitedPDF 3
  (8.96 to 9.60 μs), PDFsharp 2 (26.76 and 26.98 μs), PdfPig 1 (19.30 μs).
- All other cases reported mValue = 2 or 2.53 (no multimodal warning).

## Limitations of this run

- One run on one machine. The Balanced power plan and an interactive desktop
  mean frequency scaling and background load may have affected results.
- The libraries' outputs are not semantically identical: defaults, metadata,
  compression and object layout differ, and PdfPig returns bytes directly while
  the others serialize to a `MemoryStream` and copy (see methodology). Output
  byte size was not recorded.
- Not measured: native memory, working set, CPU usage, throughput,
  concurrency, cold start and long-running behaviour.
